# Accessibility baseline - 2026-08-24

The first keyboard, focus-visible, contrast and axe measurement this app has ever had.
Before this, the UI/UX scoring programme scored a 30%-weight dimension blind here.

> ## Coverage correction, same day
>
> **The first version of this document reported focus/keyboard numbers measured
> over 4.9% of the app's controls, and said nothing about it.**
>
> The harness enumerated each surface's focusable set, focused the controls one

## The probe proves itself before it reports

A scan that reports zero violations is worthless unless it can be shown capable
of reporting one. Every run injects a known-bad element for each detector,
requires the detector to name it, removes it, and requires the detector to stop
naming it. All 12 legs must pass or the run exits `2` and writes no report.

The self-proof used to run on `/` -- the one required surface whose focusable
population is small and static, i.e. the single route where the sample cannot
collapse. **A self-test that cannot fail on the thing it guards is worthless.**
It now runs on the first nested required surface, and its last leg fails if the
chosen route turns out to be structurally incapable of collapsing.

```
PASS contrast detector flags the injected low-contrast text
       [measured 1.92:1 (required 4.5) -> pass=false]
PASS the injected run is present BY NAME in the failing set
       [failed 1 -> 3; injected run in failing list=true]
PASS axe NAMES each injected node under its own rule (not just a new rule id)
       [color-contrast nodes 1 -> 4 names #__sp_contrast=true;
        image-alt nodes 0 -> 1 names #__sp_img=true]
PASS focus detector sees the suppressed indicator
       [active=true outline=false shadow=false]
PASS a TRANSPARENT 2px outline is NOT scored as a visible focus ring
       [visible=false transparentOutlineOnly=true outlineColor=rgba(0, 0, 0, 0)]
PASS the injected run is GONE BY NAME after removal
       [injected run still present=false]
PASS axe returns to baseline after removal (per-rule node counts, by name)
       [color-contrast nodes 4 -> 1 (baseline 1); image-alt nodes 1 -> 0 (baseline 0)]
PASS the injected controls are measured while present and absent after removal
       [before 0 -> present 2/2 -> after removal 0/0]
PASS COVERAGE: a self-destroying sample is reported as PARTIAL and named
       [status=partial coverage=7.7% measured=1/13 stale=12
        destroyedBy="sample destroyer" unaccounted=0]
PASS COVERAGE: an identical STABLE sample is reported as FULL at 100%
       [status=full coverage=100% measured=13/13 unaccounted=0]
PASS ROOT CAUSE: a tabindex="-1" roving control is not focused, sample survives
       [status=full measured=12/12 notTabReachable=1 sampleDestroyed=false]
PASS the self-proof route is CAPABLE of exhibiting sample collapse
       [route=/workspace/assistants population 20 -> 19
        autoActivationTabs=5 rovingFocusables=5]
```

Three of those legs carry the harness's own authored control content -- a focus
sample that provably destroys itself, an identical sample that does not, and a
roving `tabindex="-1"` destroyer -- so the coverage reporter is proven in both
directions on every run rather than depending on whichever app surface happens
to misbehave that day.

Two legs were replaced because they compared **quantities that the app moves on
its own**, which is a false-alarm mode that fails closed and blocks legitimate
runs:

- *"axe reports at least one NEW violation id"* compares rule-ID **sets**. On
  any surface that already reports `color-contrast`, the injected low-contrast
  text adds no new id and that half of the leg silently stops testing anything.
  Measured on `/workspace/frontend-revenue`: `violations 4 -> 5; new ids:
  image-alt`. On a surface that also already has an alt-less image the leg goes
  fully dead -- reproduced on an authored control page carrying both rules:
  `violations 4 -> 4; new ids: (none)`, `PROBE IS DEAD`, exit 2, no report
  written. It now asserts that axe **names the injected selector inside that
  rule's own targets**, plus per-rule node counts. The sibling mission-control
  harness hit the same trap and solved it the same way
  (`tests/e2e/accessibility-contract.spec.ts`, controls A and B); that approach
  is reused here rather than a third one invented.
- *"focusable population returns to baseline after removal"* compared a
  whole-page focus count. Once the self-proof moved off the static root it read
  `baseline 7 -> restored 9` and killed a healthy run. It is now scoped to the
  harness's own injected container, where the expected values are exactly 2 and
  0. The two contrast legs got the same treatment for the same reason
  (`failed 3 -> 2 (baseline 1)` on a surface whose own content changed
  mid-proof).

This is not ceremony. The self-proof caught real defects **in the harness
itself** before any number was published:

1. **A silently emptied focusable set.** A swallowed exception in the focus pass
   made every element "unusable" and the pass reported `checked: 0` — a clean
   zero produced by measuring nothing. The self-proof compared baseline against
   post-removal and refused the run. The catch now surfaces the error.
2. **A transparent outline scored as a visible focus ring.** See below.

What it did **not** catch, because it was structurally unable to, is the
coverage collapse -- it ran on the only route where the collapse does not
happen. That is fixed above, and is the reason the route-capability leg exists.

## Three corrections made before publishing these numbers

An earlier run of this harness produced different, wrong numbers. They are
recorded here because the corrections are the substance of the result.

Every figure in this section is quoted at the **4.9% coverage** of that run.
The corrections themselves still hold -- they are about how a control is
scored, not how many were scored -- but the counts are a sample of about one
control in twenty, not totals.

**1. Next.js dev-overlay contamination.** The first run attributed **16 of 16**
focus-obscured failures to a single control: the "Open Next.js Dev Tools"
button injected by the dev server. It does not exist in a production build.
Every detector now excludes dev chrome, and the app's real result is
**208/208 unobscured** — the app had no obscured-focus problem at all.

**2. A fabricated keyboard trap.** The first run reported a keyboard trap on
`/settings` at both viewports. It was a defect in the probe: trap detection
keyed on `tag|class|label|size`, and `src/app/settings/page.tsx` has four
adjacent inputs (lines 149, 166, 183, 213) that share an identical className,
identical size and an empty label. Four different controls produced one
identical key, which read as "Tab never leaves this element". Identity is now
a per-element stamp, and the corrected result is **0 traps**.

**3. A transparent outline counted as a focus ring.** Tailwind 3.4.19 compiles
`outline-none` to `outline: 2px solid transparent` (confirmed in this repo's
generated CSS). The focus check — ported from component-marketplace — tested
only `outlineStyle !== 'none' && outlineWidth > 0`, so an **invisible** outline
passed. Correcting it to require a non-transparent outline colour moved the
focus result from a reassuring 208/208 to a truthful **150/208**, surfacing 58
real defects. This flaw exists in the upstream harness too and is worth
checking in any sibling repo that uses Tailwind `outline-none`.

## Staleness: this rides `sourceDigest`, and is not yet enforced

The deliberate decision (detail in #153) is that a11y evidence should ride the
**existing** `capturedAt.sourceDigest` mechanism rather than growing a second
one — that digest already covers the route's render closure plus
`tailwind.config.ts` and `postcss.config.mjs`, which is exactly what determines
focus rings and contrast.

That wiring is **not done**. Today this document is a point-in-time baseline,
not an enforced gate: nothing forces a re-run after a UI change. Known blind
spots it will inherit — dependency bumps (a Tailwind bump is precisely what
drives the focus finding) and data-dependent rendering across the five cockpits
that share one `sourceDigest` — are recorded in #153 rather than papered over.

## Placement

On-demand, not pre-push. The harness needs a running server, so a hook would
have to skip when none is up, and a skip is fail-open — it would report success
having measured nothing. The compensating control is the self-proof above: the
harness refuses to emit a report it has not earned. That is a control on probe
*validity*, not on *cadence*; cadence is #153.

## Reproduce

```
node scripts/probe-surface-a11y.mjs --self-proof   # 12/12 legs, ~2 min
node scripts/probe-surface-a11y.mjs                # full sweep, ~25 min
```

Exit codes: `0` every surface at full coverage, `2` the self-proof failed and no
report was written, `3` the sweep ran but at least one surface was measured at
partial coverage -- the report is written and says so, and the exit code exists
so a partial sweep cannot be scripted as a complete one.

Knobs: `MCK_A11Y_SELFPROOF_ROUTE`, `MCK_A11Y_MAX_FOCUS` (0 = unbounded, the
default), `MCK_A11Y_FOCUS_BUDGET_MS` (per-surface wall clock, default 120000;
set `0` for no bound -- a genuinely exhaustive sweep of every surface is roughly
35 minutes because the cockpits carry ~1000 controls each and the pass measures
about five per second), `MCK_A11Y_FOCUS_ROUNDS`, `MCK_A11Y_MAX_TABS`.

Defaults to `MCK_BASE_URL` or `http://127.0.0.1:3021`. Read-only against the
app: it navigates, measures, and removes everything it injects. Output lands in
`artifacts/` (gitignored).

## Provenance

Adapted from component-marketplace `scripts/operator-primitives-visual-check.mjs`
(blob `ca4bcbf5028760ffb61b058331715740de7ff232`). Ported with the algorithm
intact: the focus/Tab/focus `:focus-visible` priming, the three-ancestor
outline/box-shadow walk, the `elementFromPoint` occlusion test, the WCAG tag
set, and the rule that critical/serious *incomplete* findings block rather than
pass silently.

Not ported: that harness selects contrast pairs by hand-authored
`data-contrast-background`/`data-contrast-foreground` attributes. This repo has
**zero** such attributes, so porting the selector verbatim would have measured 0
pairs and reported `minimumRatio: null` — a vacuous zero. Contrast here is
computed from computed style over rendered text, compositing ancestor
backgrounds until opaque. Its keyboard pass is also bound to that app's specific
widgets, which do not exist here, so the keyboard walk is a generic
reachability/trap/indicator traversal over each surface's real focusable set.
